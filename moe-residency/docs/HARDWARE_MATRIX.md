# 硬件档位 × 模型规模 × 速度（目标配置：**8GB 显存 + 8GB 内存**）

> **一句话结论**：在 **8GB 显存 + 8GB 内存** 上，可用快速内存只有 **12GB**
> （显存扣 1GB 给显示 ⇒ 7GB；内存扣 3GB 给 OS ⇒ 5GB）。
> 这决定了：
> - **4-bit 天花板 ≈ 24B** —— 连 35B-A3B 的 4-bit 档（17.5GB）都装不下
> - **35B-A3B 需要 2~3-bit** 才能"可对话"
> - **V4-Flash（284B）在这台机器上不可能"可对话"**：即使 1.58-bit，池 56GB 对 12GB 预算
>   ⇒ 约 **79%** 的专家要流式读盘 ⇒ 估算 **≈1.3 tok/s**（按 colibri 全盘流实测的 5~10×
>   修正，也只是"可能"到个位数，且 1.58-bit 质量已明显退化）
> - **要真跑 284B 且可对话：内存加到 ~150GB**（或 32GB 显存工作站 + 128GB 内存）

数字由 `benchmarks/theoretical_speed.py` 生成（可改 `MODELS` / `HARDWARE` 重跑）。

## 三、实测对照（这些是别人跑出来的真数字）

| 模型 | 引擎 | 硬件 | **实测 tok/s** | 出处 |
|---|---|---|---|---|
| Qwen3.6-35B-A3B | llama.cpp（LFRU）| RTX 5060 8GB + **32GB** | **34.9** | 社区实测 |
| Qwen3.6-35B-A3B | FreeToken | 8GB 显存笔记本（内存更多）| **39.3** | FreeToken 论文 |
| DeepSeek-V4-Flash 284B | FreeToken | 32GB 显存 GPU（**池需在 RAM**）| **22** | FreeToken 论文 |
| GLM-5.2 753B | FreeToken | 96GB 显存 GPU | **14.9** | FreeToken 论文 |
| Qwen3.8-Flash-Next 125B | Strata | RTX 5070 12G + 64GB @2bit | 60–95（宣传值，含投机解码）| Strata |
| Qwen3.8-Flash-Next 125B | FreeToken | RTX 5090 | **50**（prefill 2300）| 社区实测 |
| GLM-5.2 744B | colibri | 6×RTX 5090，全驻留 | **5.8–6.8**（TTFT 13s）| colibri |
| GLM-5.2 744B | colibri | 128GB **纯 CPU** | **1.8** | colibri |
| GLM-5.2 744B | colibri | 单卡 5070Ti 笔电 | **1.07** | colibri |
| GLM-5.2 744B | colibri | **25GB 笔电（全盘流）** | **0.05–0.1** | colibri（其 README 自承）|

> ⚠ 注意对照：上表里 **35B-A3B 的两个实测都配了 ≥32GB 内存**。
> **8GB 内存的机器没有任何公开实测**——本表 35B-A3B@3-bit 的 ~27 tok/s 属于**乐观理论值**
> （未建模 CPU 上的专家计算与页缓存抖动）。

**agent 场景的首 token 延迟（TTFT）**同样被分层策略主导：
FreeToken 最差 **<44s** vs llama.cpp **232s** vs KTransformers **946s**。

## 四、模型与校准（本表对磁盘流式偏保守）

| 场景 | 本表估算 | 实测 | 偏差 |
|---|---|---|---|
| GLM-5.2 744B@int4，25GB 笔电（全盘流）| ~0.015 | **0.05–0.1** | 本表低 5–10× |
| Qwen3.6-35B-A3B，8GB 显存 + 32GB 内存 | 未单列 | **34.9** | — |

偏差原因：colibri 走**大 slab 顺序读**（单专家 ~19MB）+ 页缓存 + I/O 流水线，本表未建模这三项。

**⇒ 磁盘流式档以实测为准；本表的价值在于给出「断崖的位置」与「量级」。**
