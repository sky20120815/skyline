# 设计说明

## 1. 问题

MoE 的专家池远大于显存。分层卸载把专家按热度放在三层：

```
VRAM（快，几十 GB/s 级）→ RAM（中）→ SSD（慢，消费级 NVMe 约 2–7 GB/s）
```

每 token 只把路由到的 `top_k` 个专家取到快层计算。三个问题必须回答：

1. **取谁、留谁、下一个预取谁？**（策略）
2. **怎么证明"换个层级放"不改变输出？**（验证）
3. **怎么衡量策略好坏？**（指标）

本仓库分别用 `policy.py` / `verify.py` / 两类指标来回答。

---

## 2. 为什么"单块 MoE"对磁盘层天然友好

每 token 的专家搬运次数 = `MoE 层数 × top_k`：

| 架构 | 层数 | top_k | 每 token 专家读 |
|---|---|---|---|
| DeepSeek 类（常规深层 MoE）| ~60 | 8 | **~480 次** |
| 本项目（单宽专家块）| **1** | 4 | **4 次** |

同样激活参数量下，**单块结构把磁盘压力量级降低两个数量级**。
这是本仓库 `engine.py` 只实现单块 MoE 的原因 —— 它不是简化，而是这类架构的真实形态。

（代价：单块无法利用"逐层不同专家组合"的表达力，需要靠更大的专家池与更强的路由补偿。）

---

## 3. 指标：为什么必须区分「停顿 miss」和「预取 I/O」

预取的本质是**用带宽换延迟**：

- 它**增加**总读盘量（提前读了可能还没用到的专家）
- 它**减少**停顿（读盘发生在计算期间，不等）

所以用「读盘次数」评价预取必然得出"预取更差"的错误结论。正确做法：

| 指标 | 含义 | 用途 |
|---|---|---|
| **停顿 miss** | 需要专家时它不在快层，必须当场等 I/O | 决定用户感知的快慢 |
| **预取 I/O** | 提前搬运的字节数 | 算进带宽预算，但不计为停顿 |
| **预取浪费** | 预取后未被使用 / 被提前淘汰 | 评价预取质量的唯一负面指标 |

`examples/demo_engine.py` 同时打印前两项，并在结论里指明第三项的含义。

## 4. 三条实现纪律（踩过的坑）

### 4.1 驻留集合只能有一个主人
如果 policy 和存储层各自维护 LRU，两者的淘汰决定会打架：policy 认为某专家还在，存储层已经把它踢了。
**约定**：`policy.resident()` 是唯一真相，存储层每步 `retain()` 对齐。

### 4.2 预取必须同步进"驻留集合"
预取把专家放进缓存后，若下一步 `retain()` 不认识它，就会立刻被踢掉 —— 白读一次。
`profile.py` + `policy.switch_domain()` 的设计保证了这一点。

### 4.3 策略在路由**之前**介入
`switch_domain(hot_ids)` 必须在路由计算前调用，否则预取没有时间窗口可供重叠。
真实引擎里这里应该是**异步**发起（本参考实现为同步返回，便于验证）。

## 5. 逐位不变：保证什么、不保证什么

**保证**：同一份权重、同一输入，无论专家从哪一层取来，logits **逐位相同**
（`verify.py` 用 float32 字节的 sha256 比对）。

**不保证**：
- 量化/压缩引入的误差（int4/int8 会改变数值，需要的是误差界而非逐位相等）
- 不同 batch/并发顺序下的浮点归约差异
- 内核实现差异（如 SDPA 反向的原子累加，本身就不逐位可复现）

这条边界很重要：**"放置不改语义"和"压缩不改语义"是两个不同强度的承诺**，本仓库只做前者。

## 6. 负载与策略匹配表（实测归纳）

| 负载特征 | 首选策略 | 原因 |
|---|---|---|
| 单域、稳定、缓存足够 | `lru` | 最近使用≈最常使用，策略收益 <4% |
| 工作集略大于缓存、有突发 | `slru` | protected 段保护稳定热专家，实测 −17% |
| 多任务/agent 频繁切域 | **`prefetch`** | 切域后的一批冷 miss 可提前搬走，实测 −24% |
| 存在**全局**长热热点 | `pinned` | 热热点被 pin 后不再与冷专家争槽位 |
| 全局热点 + 切域 | `pinned_prefetch` | 两者叠加，但 pin 会挤占 LRU 槽位，需调 `pin_frac` |

**没有万能策略**。`benchmarks/policy_bench.py` 就是用来在**你的**负载上选型的。
